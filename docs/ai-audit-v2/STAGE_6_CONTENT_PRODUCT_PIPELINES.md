# Этап 6. Контентные и продуктовые pipeline

Дата завершения реализации: 26 июля 2026.

## Что реализовано

- `product_main`: `TERRA -> LUNA -> TERRA`, 60 AI-баллов.
- `product_mini`: `TERRA -> LUNA -> TERRA`, 80 AI-баллов.
- `lead_magnet`: `TERRA -> LUNA -> TERRA`, 70 AI-баллов.
- `chatbot_scenario`: `TERRA -> LUNA -> TERRA`, 30 AI-баллов.
- `tg_channel_plan`: `TERRA -> LUNA`, 40 AI-баллов.
- `selling_post`: `TERRA -> LUNA`, 10 AI-баллов.
- `content_article`: `TERRA -> LUNA -> TERRA`, 30 AI-баллов.
- обычный `youtube_script`: один этап `LUNA`, 35 AI-баллов.
- продающий `youtube_script_selling`: `TERRA -> LUNA -> TERRA`, 50 AI-баллов.

Для каждого этапа заданы отдельные output limits. Между стадиями передаётся ограниченный структурированный результат, но длинный черновик больше не обрезается до 4 000 символов: размер handoff вычисляется из output limit и ограничен 30 000 символами.

## Продуктовые сборки

Основной продукт, мини-продукт и лид-магнит больше не собираются серией отдельных пользовательских генераций. Кнопка сборки запускает один workflow:

- `product.main.build`;
- `product.mini.build`;
- `leadmagnet.build`.

Одна сборка создаёт один финальный документ, один final artifact и одно фиксированное списание. Внутренние стадии и retries влияют только на техническую себестоимость.

Ручные и AI-правки используют отдельные action keys:

- `product_main_edit`;
- `product_mini_edit`;
- `lead_magnet_edit`.

Каждая такая правка стоит 10 AI-баллов и не запускает полную пересборку.

Frontend сохраняет ответ aggregate workflow в `currentMarkdown`. Просмотр, `Мои материалы`, DOCX и PDF используют эту актуальную версию.

## Безопасность списания

Последовательность успешной операции:

1. Резерв AI-баллов.
2. Выполнение внутренних стадий и retries.
3. Финальная валидация.
4. Сохранение final artifact и пользовательского structured output.
5. Capture одного фиксированного списания.

Если финальная валидация не прошла, final artifact не создаётся, capture не выполняется, резерв освобождается, workflow получает статус `FAILED`.

## UI стоимости

Серверная стоимость показывается перед запуском:

- в конструкторах трёх продуктов;
- при написании статьи;
- при создании видеосценария;
- при создании цепочки чат-бота;
- в ранее подключённых постах и плане ТГ-канала.

Компонент котировки поддерживает `inputs`, поэтому backend может показать разную цену для обычного и продающего сценария.

## Проверки

- Контрактные unit tests для всех Stage 6 pipeline, алиасов и output limits.
- Integration contract test для workflow registry, action resolver и фиксированной цены каждого pipeline.
- Тест отдельных action keys продуктовых правок.
- Тест порядка `final artifact -> capture`.
- Тест ошибки финальной валидации: нет artifact/capture, резерв освобождается.
- Backend и frontend production builds.

## Включение

Реализация защищена существующими флагами `AI_ORCHESTRATION_V2`, `AI_POINTS_V2`, allowlist пилота и `AI_ORCHESTRATION_V2_ACTIONS`.

Этап не включает автоматическое включение production-флагов. Перед широким rollout нужно пройти пилот этапа 5, проверить реальные расходы и только затем расширять allowlist.
